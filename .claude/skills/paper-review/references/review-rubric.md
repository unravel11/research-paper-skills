## 1. 通用状态与证据上限

每个 gate 只能使用：

- `PASS`：已有直接、当前、可核验的充分证据，并给出证据指针。
- `PARTIAL`：有相关证据，但范围、独立性或完整性不足。
- `FAIL`：已确认与要求冲突、违反冻结协议，或核心证据链断裂。
- `ABSTAIN`：材料不足或权威不明，不能判断。

禁止把 `ABSTAIN` 当作 `PASS`，禁止为得到总分而给未知项估值。validator 通过、PDF 能编译、表格齐全，只是各自机械属性的证据。

证据类别与通常允许的最高措辞：

| 证据类别 | 通常可辩护的最高措辞 |
|---|---|
| `VERIFIED_CURRENT`，当前真实证据加独立或权威参照 | 观察到的版本、配置、人群下的有界发现 |
| `CONTROLLED_OR_RETROSPECTIVE` | 受控或回顾性行为，不自动是真实部署结论 |
| `EXPLORATORY_OR_CANDIDATE` | 候选，需验证；不承担主张 |
| 配置条件下的发现 | 条件性结论，写明配置 |
| 阴性结果 | 在冻结的测试范围内未见正效应，不是普遍安全或普遍无效 |
| `MISSING_OR_UNRESOLVED` | 未知，保留分母，不删 |
| `SUPERSEDED_OR_INVALID` | 对当前主张无支撑 |

## 2. 一级 L1：framing 与补实验决策

### L1-G0 权威与快照
论文基线、实验版本、当前与历史结果能否区分；有没有未推送提交、脏工作树、相互冲突的状态文档；被废止结果是否已从当前证据隔离。权威不明即 `ABSTAIN`。

### L1-G1 研究问题与对象
问题是否具体、重要，并属于目标 venue 的领域；目标对象、任务、使用情境和评价单位是否清楚；研究的是方法、评测协议、经验规律、数据基础设施还是系统实践，不混为一个贡献。venue 档案可附加领域专有要求，例如安全 venue 要求写明保护对象与信任边界。

### L1-G2 核心 framing 与主张上限
能否用一句话说清研究什么、为什么重要、通过什么证据回答；标题、摘要、RQ、实验和结论是否在同一 estimand 上；当前 framing 是否依赖证据没有证明的 SOTA、因果、普遍泛化或忠实复现；每个 load-bearing 主张是否映射到当前证据及其 provenance。

### L1-G3 framing A/B 潜力门
A 是当前最强的忠实定位，B 是同一证据支撑的最强保守替代。选 `A` / `B` / `NO_CREDIBLE_FRAMING` / `ABSTAIN`，说明哪些主张保留、削弱、删除。

### L1-G4 主张与证据覆盖
每个核心主张至少一条直接证据；主要结果是不是诊断、上界或受控条件却被写成端到端能力；负结果、污染、替代结果和边界是否诚实纳入；有没有没有实验支撑却承担摘要或贡献的 load-bearing claim。

### L1-G5 贡献可区分性与最近工作差异
贡献写成具体的能力、发现、方法、数据集、评测或实践含义；与最接近的同任务工作和已发布 artifact 比较，比较单位一致；没有 faithful baseline 时是否已转成审计、受控重实现或实证评测贡献；新术语没有差异支撑是 `PARTIAL` 或 `FAIL`；贡献是否超出"跑了更多模型或数据"。

### L1-G6 读者价值与 venue 适配
对目标 venue 的读者提供什么可复用的方法、证据、设计原则、失败模式或实践含义；深度是否超过一个数据集上的排行榜；结论能否在限定范围内形成连贯的论文故事。具体问题由 venue 档案给出。这一门评的是适配，不是接收。

### L1-G7 实验充分性
只检查对当前 framing 负载关键的实验：主比较是否公平且估计对象一致；关键替代解释是否至少有一个能区分它的分析或干预；必要的稳定性、不确定性和错误分析是否存在；外部、时间、来源泛化若是核心主张，是否有对应证据；新实验是否真能改变论文决策。

### L1-G8 可写性、一致性与停止规则
当前证据能否组成问题、方法、结果、含义的完整链；哪些结果进正文、附录、限制或删除；摘要、引言、方法、结果、讨论、限制、结论、图表与 artifact 声明描述的是否同一个有界研究；是否到了"继续补实验的边际收益低于收敛论文"的点；核心 framing 失败时是否停止局部修补进入重构。

### L1-G9 可复现性、伦理与披露边界
命令、版本、机器可读结果、裁决记录和 artifact 边界是否足以支撑所声称的内容；人类受试、漏洞披露、敏感细节、许可和发布授权在相关时是否明确处理。

### L1 前瞻用法（R1，实验之前）
材料是 FRAMING、STORY_SPINE 与 VENUE_PROFILE，不是结果。G4 与 G7 改为检查：判定规则与结果中性检查是否已写定；基线是否当前最强版本；两个分支是否都有读者会改变的判断和去处。档位加"前瞻"后缀，试点或 R3 之后重新给档。补实验决策在此只有 `TARGETED_EXPERIMENTS`（进入 R2）或 `MAJOR_REDESIGN`（回 paper-framing）。

## 3. 二级 L2：证据链审计

L2 除全部 L1 门外，逐项审计从对象到结论的证据链。十门对所有研究类型通用；每门在不同类型里具体审什么，按 [l2-by-method.md](l2-by-method.md) 对应研究类型的小节，研究类型从协议第一行读。

| Gate | 核心问题 |
|---|---|
| L2-G0 协议冻结与偏离 | 协议或分析计划在接触确认性结果之前冻结；偏离登记了日期、理由、谁决定、影响；为找结果而改的地方是否披露并与确认性结果分开 |
| L2-G1 对象、样本与分母 | 研究对象或数据从哪来、怎么选、分母是什么；排除、缺失、失败、未决案例能否重建；便利样本不支撑总体结论 |
| L2-G2 真值、度量与标注 | 结论依赖的“真”从哪来，是否独立于被评的对象；度量测的是不是要测的东西；标注过程、标注者独立性、分歧与信度可见；机器诊断不升级为人工判定 |
| L2-G3 隔离与泄漏 | 探索与确认是否隔离；做决定前分析者看过什么；结果信息有没有泄回对象选择、配置或假设 |
| L2-G4 分析单位与配对 | 在哪一层比较、在哪一层重复；重复是不是独立的；同池比较与端到端比较分开 |
| L2-G5 过程受控 | 影响结果的过程（调参、编码本版本、访谈者行为、工具配置、证明假设的变更）是否受控并有记录 |
| L2-G6 对照、替代方案与消融 | 对照或替代方案公平且不是稻草人，可恢复；竞争解释被排除；消融或反例与所声称的机制对应 |
| L2-G7 判定、统计与不确定性 | 判定按协议规则得出；区间与变异而不只是点估计；多重比较与效应量；定性的饱和与信度；没有设计支撑不用因果或总体语言 |
| L2-G8 稳健性与外部效度 | 敏感性、失败案例、配置或情境边界是否报告；阴性门保留；结论限定在观察到的范围 |
| L2-G9 复现链、材料与披露 | 关键数字可从材料重建；脚本、材料、版本有指纹；数据与材料的可得性和限制写明；伦理、披露、私有证据与科学结论分开 |

venue 档案可以追加链门，例如安全 venue 的运行时与真实产品证据。

L2 必须输出处置表：`保留正文 / 降级表述 / 移入附录 / 历史保留 / 禁止使用 / 未解决`，每门报告：

| Gate | 状态 | 直接证据 | 科学影响 | 最小补救或停止条件 |
|---|---|---|---|---|

## 4. 三级 L3：投稿前模拟审稿

只对完整稿或接近完整稿做；否则降级为 L1 或 L2，不给投稿推荐。

| Gate | 核心问题 |
|---|---|
| L3-G0 完整且绑定的快照 | 稿件完整到可以做审稿决定，并绑定具体快照；缺 Results、Related Work、Validity 或核心证据通常 `ABSTAIN_INCOMPLETE_MANUSCRIPT` |
| L3-G1 venue scope、读者与价值 | 论文回答目标 venue 读者会用到或学到的问题；scope 按当前官方材料核对 |
| L3-G2 新颖性与定位 | 最接近的同任务工作、具体差异、不以改名制造新颖性；引用覆盖与事实定位有证据 |
| L3-G3 方法正确性 | 定义、假设、算法、协议与实现匹配主张；循环或不独立的真值是 load-bearing 缺陷 |
| L3-G4 实验与有效性 | 实验用合适的数据、基线、指标、统计、稳健性检查和外部效度边界回答研究问题；阴性与未决案例可见 |
| L3-G5 主张一致性与限制 | 所有章节、图表、图注与补充材料在同一上限内；限制具体，不掩盖中心无效性 |
| L3-G6 渲染后的版面与图表 | 渲染 PDF：图一在前两页且能单独讲出转折；表格与字号可读、未被压缩；配色一致；症状清单全否 |
| L3-G7 artifact、伦理与披露 | 可复现性与 artifact 声明符合实际；披露、敏感细节、人工审查、利益冲突、数据权利、发布授权有界 |
| L3-G8 当前投稿要求 | 按官方来源协议核验当前 scope 与规则，带日期与 URL；访问失败只对本门 `ABSTAIN` 并列出未核实项 |
| L3-G9 拒稿风险与推荐 | 按影响递减列前三条 load-bearing 拒稿风险，各带证据与后果；给一个允许的推荐，不给接收概率 |

推荐只能是 `GO_INTERNAL_REVIEW` / `GO_AFTER_TARGETED_REVISIONS` / `NO_GO_MAJOR_REVISION` / `NO_GO_EVIDENCE_GAP` / `ABSTAIN_INCOMPLETE_MANUSCRIPT`。它们不是对真实决定的预测。当前规则状态单独报 `VERIFIED_CURRENT` / `ABSTAIN_NOT_VERIFIED` / `NOT_REQUESTED`，科学推荐与管理弃权可以并存。

## 5. 潜力档位

L1 与 L3 各给一个：

- `P3_STRONG`：保守主张下证据链完整，贡献清楚，venue 适配清楚；无需新增核心实验或只需小型补分析。
- `P2_VIABLE_CONDITIONAL`：存在可信的论文核心，一到两个明确缺口阻止当前投稿。
- `P1_WEAK_OR_UNFOCUSED`：有材料但 framing 分散、贡献弱、差异或适配不足；需要重构后再判断。
- `P0_NO_GO_CURRENT_DIRECTION`：当前 framing 与证据根本不匹配，继续局部补实验不合理。
- `PU_ABSTAIN`：缺少足够材料。

档位由门解释，不能平均。任何 load-bearing `FAIL` 通常不高于 P1；load-bearing `ABSTAIN` 通常不高于 PU 或 P1，除非明确限定为只评研究方案。前瞻用法的档位标"前瞻"，与对已有证据给的档位分开。

## 6. 补实验资格门与实验卡片

只有同时满足以下条件，才给出 `TARGETED_EXPERIMENTS`：

1. 至少一个 framing 达到 P2 或有清晰的 P2 路径。
2. 缺口对应核心主张，而不是"审稿人可能喜欢"。
3. 实验有独立于期望结果的协议和判定规则。
4. 正、负、无差异结果都预先对应论文处置。
5. 有明确停止规则，不以寻找显著性或正结果为目标。
6. 不需要未经授权的 held-out、外部 API、人工标注或大规模运行；需要时先请求授权。

每个合格实验用卡片：

| 字段 | 内容 |
|---|---|
| Claim gap | 填补哪个核心主张缺口 |
| Minimal design | 最小数据、比较、指标和统计 |
| Independence | 协议、生成器、validator 如何独立 |
| Positive action | 若支持，论文如何改变 |
| Negative action | 若不支持，论文如何收缩或转向 |
| Stop rule | 何时停止，不再扩大实验 |
| Claim ceiling | 无论结果如何仍不能声称什么 |
| Dependencies | 授权、安全、算力、人工或外部依赖 |

## 7. venue 附加门怎么接

venue 档案可以增加门，ID 用 venue 缩写做前缀，例如安全应用期刊的 `<缩写>-G1 威胁模型与后果`、软件工程期刊的 `<缩写>-G1 对实践者的可复用价值`。附加门与核心门同一套状态值，一起进报告的 gate 表和 JSON 记录；validator 允许核心门之外的任何 `<前缀>-G<n>` 门。没有档案的 venue 只用核心门，并在报告里写明"venue 未建档，适配判断按通用读者价值"。
