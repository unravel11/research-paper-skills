# 创新点探讨（Innovation Explore）

核心：先喂高质量上下文，再严格锁定阶段，最后由用户的 taste 多轮迭代。
模型的职责是提供可比较的候选和清晰的来源链，不是替用户判断什么是创新。

## 0. 阶段锁（最高优先级）

当前是**创新点探讨阶段**。在用户明确宣布进入下一阶段前：

- 严禁输出：实验方案、数据集/基线/指标选择、公式推导、伪代码、论文结构、相关工作段落、防御式声明（"与 X 的区别在于……""可能的审稿质疑……"）、投稿建议。
- 严禁调用其他阶段的 Skill（paper-framing、paper-writing-orchestrator、paper-reading 的完整报告模式等）。读文献只用本 Skill 第 2 步的压缩格式。`research-pipeline` 例外：它只做阶段记录与路由，退出时可以调用。
- 严禁一次性给出"完整方法"。每轮只推进一层。
- 用户追问本阶段以外的内容时，只回答一句并提醒当前阶段，不展开。
- 异常入口里的排伪像与复现刻画是诊断，不是实验设计：只用已有的材料、配置和脚本（数据、记录、代码、证明草稿都算），不引入新方法、不选基线或对照、不定论文指标，产出标 exploratory。见 [anomaly-entry.md](references/anomaly-entry.md)。

## 1. 明确主题与条件（用户负责）

要求用户给出：研究主题；当前依赖的假设或条件（数据形态、可用信号、部署约束等）；已经排除的方向。
缺项就追问，不要自行补默认值。把确认后的内容写成 ≤5 行的"研究设定"，后续每轮引用它，不重述。

**入口选择。** 用户带来的是主题，走第 2–5 步。用户带来的是一个观察（一条不太对的曲线、一个反常的比例、一次解释不了的失败、几句与文献相反的话），先走 [异常入口](references/anomaly-entry.md) 的 A–C：写观察句、排伪像、复现刻画；伪像排除后，以现象为检索词从第 2 步接回来，文献的作用变成"有没有人报告过、在什么条件下"。两条路最后都落到同一张四问潜力卡。大多数异常最后是错误或伪像，这不是浪费：排伪像表随方向进入 R1，paper-framing 直接引用。

## 2. 读取文献（子代理，压缩回传）

文献来源默认是**本地 PDF**，直接读文件，不需要 Zotero 或 MCP。先问用户用哪些目录；常见位置是项目内的 `literature/`、`papers/`、`pdf/`，或项目约定的共享文献库目录。列出候选：

```bash
find <目录> -iname '*.pdf' | sort       # 文件名通常带年份与引用键
```

目录里有清单或台账（如 `manifests/`、`README.md`、`FILES.tsv`）时，先用它取题名与作者，不靠文件名猜。

可选：用户的文献已在 Zotero 里按项目整理（一个项目一个顶层集合，集合名 = 项目目录名）时，也可以用脚本取条目与 PDF 路径：

```bash
python3 <skill_dir>/scripts/zotero_list.py --collection "<集合名>"   # 或 --search "<关键词>"，不传参数列出全部集合
python3 <skill_dir>/scripts/zotero_import.py <文献目录>               # 只在用户要求把 PDF 导入 Zotero 时使用；传项目根目录只列出候选文献目录，不导入
```

导入片段需要**用户本人**在 Zotero → 工具 → 开发者 → Run JavaScript 中运行；不要替用户运行。

得到条目及 PDF 路径后，交给低成本子代理阅读（Claude Code 用内置子代理并选较小的模型，Codex 用低成本子代理或按 AGENTS.md 规则）。每篇只回传固定 4 行，禁止长摘要：

```
[编号] 作者 年 · 标题
场景：研究对象/数据/约束是什么
机制：核心做法一句话
可迁移：和本研究设定最接近的一点；若无，写"无"
```

主线程只保留这份清单，不把 PDF 原文或长笔记拉进上下文。20~30 篇以内足够；超出时让用户先缩小范围（目录或集合）。

## 3. 用户筛选（human in the loop）

按"场景相似度 + 迁移难度"把文献排序，列出前 3~5 篇并一句话说明入选理由，**停下等用户确认或替换**。用户没确认前不进入第 4 步。

## 4. 候选思路（短、可比、有来源）

基于用户保留的文献，给出 3~5 个候选，每个严格 ≤3 句：

```
思路 N：迁移自 [编号]。把 <它的机制> 用到 <本设定的哪个位置>，解决 <本设定的哪个具体问题>。
```

硬性排除，不列出：训练技巧、工程步骤、超参/损失函数微调、把两篇方法简单拼接而没有解决本设定特有问题的组合。
不写公式，不写实验，不用长难句，不加防御式声明。
输出后**停下**，等用户挑选 1~2 个。

## 5. 逐层展开（渐进式披露）

只展开用户选中的思路。每轮只加深一层，顺序固定：

1. 它解决的问题为什么在本设定下成立（一段）。
2. 迁移时必须改动的地方和不能照搬的地方（各 2~3 条）。
3. 最可能站不住的一个假设，以及用什么最小证据能判断（1~2 句）。

每层结束停下等用户反馈；用户否定就回到第 4 步换候选，不替用户辩护。

## 6. 落盘（跨会话、跨工具复用）

把当前状态写入项目内 `docs/innovation-log.md`（不存在则创建），结构见 [references/innovation-log-template.md](references/innovation-log-template.md)。
恢复会话时先读该文件，直接从记录的步骤继续，不重跑前面的步骤。Claude 与 Codex 共用这份文件。

## 退出

用户说"进入 framing / 设计实验 / 开始写"时，本 Skill 结束。退出前：

- 把排序后的 2–3 个方向写进 innovation-log 的"最终选定"，每个方向带一张四问潜力卡：重要在哪、谁在乎；合理的进攻路线（就是前提条件）；最脆弱的假设与最小判别证据；答案反过来是否仍有人在乎。不写 venue 和投稿建议，那是 R1 的事。手里留两三个方向，是因为试点可能否掉第一个。
- 项目里有 `research/STATE.md`（`research-pipeline` 的阶段状态）时，把 R0 的三条门槛（方向已选、前提条件已写、已排除方向有理由）填进"门槛核对"，下一步写"调用 $paper-framing（R1）"。
- 用一句话提示下一阶段：先由 `$research-pipeline` 核对 R0 → R1 门槛，再调用 `$paper-framing`；不替用户启动。
