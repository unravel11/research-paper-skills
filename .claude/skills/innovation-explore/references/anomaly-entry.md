# 异常入口：从一条不太对的曲线起步

研究常常不是从主题开始，而是从一个解释不了的观察开始：少数类别越训越差、换个 prompt 效果就没了、两个指标方向相反、某个子集的错误率高得离谱。这类观察大多数最后是 bug 或伪像，少数是现象。这个入口的任务是用尽量小的代价把两者分开，再把现象变成可以进 R1 的方向。顺序不能反：先排伪像，再谈重要性；先刻画现象，再查文献；先有潜力卡，再谈方法。

阶段锁照旧：这里的检查是诊断，不是实验设计。只用已有的数据、配置和脚本，不引入新方法，不选基线，不定论文指标；预算和停止规则写明；所有产出标 exploratory，不进论文证据。检查由用户或项目自己的运行脚本执行，本 skill 只列检查、读回执、填表。

## A. 写观察句

一句没有解释的话：在什么数据、模型、设置和指标上，看到了什么，和预期差多少，第一次看到是什么时候，原始曲线、配置和日志在哪。不写"因为"。原始文件原样保留，不覆盖；以后每一次重跑都是新文件。同时写下这个异常是怎么被挑出来的：看过多少配置、多少曲线。看得越多，它越可能只是选择效应。

## B. 排伪像

先列最可能的伪像来源，每条写一个与假设无关的检查，以及"什么结果能排除它"。常见来源：

| 来源 | 典型伪像 | 便宜的检查 |
|---|---|---|
| 数据 | 训练与评测重叠、同一样本重复、标签错误、预处理在两组不一致、分布漂移 | 哈希去重与重叠统计；抽样人工核对标签；逐项对比两组预处理配置 |
| 分母 | 少数类别或低频词样本太少，一两个样本就能让指标摆动 | 报告每个子群的 n 与区间；按 n 过滤后再看趋势 |
| 配置 | 种子没变、配置文件没更新、checkpoint 选错、early stopping 条件不同 | 对比实际加载的配置与日志里的参数；两个结果完全一致先怀疑配置没更新 |
| 评估 | 指标定义与直觉不一致（宏平均对微平均）、聚合方式掩盖子群、评估脚本口径变过 | 用第二种实现重算一次；分子分母逐项核对 |
| 运行 | 被抢占后从错误状态恢复、混合精度、库版本不同 | 查运行回执与重启记录；固定环境重跑一次 |
| 选择 | 看过很多配置后挑出来的那个"异常" | 写下看过多少配置、怎么挑的；这决定它只能叫探索性观察 |

每条检查做完填结果：排除 / 未排除 / 未查。全部填完之前不下结论。留下"未排除"的，进 R1 时写进前提条件，不假装不存在。给这一步一个预算，到了就停下向用户汇报；排伪像花掉几周是常态，不是失败。

## C. 复现与刻画

伪像排除后，用最小代价回答三个问题：换种子还在吗；换一个数据集、模型或设置还在吗；什么条件下出现、什么条件下消失。结果写成一张现象卡：条件、幅度、稳定性、边界。幅度带区间与 n；单种子只能叫单种子观察。这一步仍然不设计方法，也不解释机制。

## D. 现象变问题

- 这个现象反驳或限定了读者现有的哪个信念？信念的来源是什么：文献、工业实践、常用默认设置。
- 如果它成立，谁会改变什么判断；如果它最终被某个解释说明了，那个解释本身是否仍有人在乎。
- 文献对照：以现象为检索词，用本 skill 第 2 步的压缩格式读最接近的几篇；结论只有三种：已被报告（在什么条件下）、部分报告、未见报告（标待核实）。已被完整报告不等于没有方向，剩下的可能是边界或解释。

## E. 潜力卡

和主题入口同一张四问卡：重要在哪、谁在乎；合理的进攻路线（手里已有可复现的现象，这是异常入口天然的优势）；最脆弱的假设与最小判别证据（通常是"还有没想到的伪像"和"换最强基线或更大规模后还在不在"，这两条就是 R2 试点要做的）；答案反过来是否仍有人在乎。写进 innovation-log 的"最终选定"，和文献迁移来的方向一起排序。

## 退出

同主题入口。多一条：排伪像表和现象卡随方向进入 R1，`paper-framing` 的"恢复证据与选择历史"直接引用它们，不重做；现象卡里的条件和边界就是 R1 骨架里张力与分支的素材。
