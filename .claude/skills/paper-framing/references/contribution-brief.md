# 贡献简报（Contribution Brief）

用途：让作者、合作者或新接手的人在两分钟内弄清"这篇论文想讲什么、哪些已经站得住、哪些还悬着、哪些不能说"。它是 FRAMING 的派生物，不新增主张，不替代 FRAMING 的 RQ 表、基线表和竞争解释表。

什么时候输出：

- 用户问"这篇论文的主要贡献和创新点是什么""文章想讲什么""输入输出是什么"——先给简报，再按需要展开 FRAMING 的其他部分。
- 每一轮 framing 结束时，作为交付的第一页。
- 主张、证据或分配发生变化（新结果、回退、换方向、与同团队另一篇重新切分）之后，重写一份，旧版归档。

## 模板

```markdown
## 贡献简报（<日期>，依据：FRAMING <版本> / 台账 <ID>）

**中心问题**：<一句，带人群 / 设置 / 条件>

**输入 → 处理 → 输出**：
<方法或研究拿到什么材料（数据、源码、日志、文档、访谈记录……），对它做什么，产出什么形态的结果（候选项、确认结果、分类、测量值、证明……）。三行以内。>

**已经站得住的贡献**
1. <主张一句> — 证据：<可追到文件或 ID 的事实> — 性质与边界：<事后 / 前瞻；探索性 / 预注册；样本来源；不能推到哪里>
2. …

**还没定的贡献**（如有）
| 待判项 | 判定条件 | 判成时的措辞 | 判败或不确定时的措辞 |
|---|---|---|---|

**不能声称**
- <说法> — 因为 <近邻工作 / 证据等级 / 归属 / 披露约束>
- …

**唯一能写的窄差异**：已有工作在 <X> 下说明 <Y>；本研究在 <Z> 下进一步回答 <Q>，证据为 <E>。

**与同团队其他论文的分界**（如有）
| 成果 | 本文 | 另一篇 |
|---|---|---|

**待用户决定**（会改变上面任何一条的）
- …
```

## 写法规则

- 每条贡献 ≤3 句：主张、证据、性质与边界各一句。证据写事实（数字、ID、文件），不写形容词。
- "站得住"与"还没定"必须分开。判定条件写死在前，不同结局各给一种措辞，不在看到结果后再想。
- "不能声称"每条都带原因；原因只能是四类之一：近邻工作已做（给出处）、证据等级不够（给等级）、归属不在本方法（给实际来源）、披露约束（给状态）。
- 输入→处理→输出用普通名词写，不用项目内部的阶段名、缩写或代号；读者是第一次见这篇论文的人。
- 两条标注轴照 SKILL.md §2：认识状态（事实 / 推断 / 假说 / 未知）和产生时点（事前 / 事后）。简报里用一个词标在性质栏，不展开。
- 分界表只在同团队有共用材料的另一篇时写；原则是同一项成果只在一篇里计数，另一篇引用。
- 简报里不出现 venue、投稿建议、录用预期；那些在 VENUE_PROFILE 和 R5。
- 读者问"为什么 X 不能算"时，答案应该已经在"不能声称"里；如果不在，补进去，不要只在对话里解释。

## 与 FRAMING 各节的对应

| 简报栏 | 来自 FRAMING |
|---|---|
| 中心问题 | 一句话主张 |
| 输入 → 处理 → 输出 | 潜力卡"不用术语说在做什么""现在怎么做" |
| 已经站得住的贡献 | 研究问题表中已有答案的行 + 论证链 |
| 还没定的贡献 | 研究问题表中判定规则已写、结果未出的行；R3 结算前的分支 |
| 不能声称 | 明确不主张什么 + 最近工作差异表 |
| 唯一能写的窄差异 | 最近工作差异（D 步）的收束句 |
| 分界 | 选择史 / 与同团队其他论文的分配记录（如有） |
| 待用户决定 | 待用户决定 |
