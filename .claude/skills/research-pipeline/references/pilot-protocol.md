# R2a 试点：先用小代价判断分支，再冻结确认协议

试点回答三个问题：这条路线做得通吗；效应量大概多大，阈值放哪；骨架的哪个分支更可能成立。它不回答"主张成立吗"。注册式报告允许 Stage 1 带试点数据，前提是与正式实验明确区分；这里同样。

## 规则

- 只用 dev 或单独划出的试点集，不碰 test；保护集规则与正式协议相同。
- 写预算上限（配置数、种子数、算力、时间）与停止规则，到了就停，不"再试一个"。
- 所有产出标 `exploratory`，进台账时状态是 `EXPLORATORY_OR_CANDIDATE`，不能作为论文证据；论文里最多作为"试点数据"出现，并与正式实验分开。
- 试点看到的效应只能用来写确认协议里的阈值、种子数、功效估计和分支选择；不能据此改主要比较的方向去凑正结果。写进确认协议时标明"来自试点"。
- 试点结论写回 FRAMING 的潜力卡（重评档位）与 STORY_SPINE（哪个分支更可能），版本留痕。
- 可以免做：数据与方法都有同类先例、潜力卡把风险判为低，由用户决定，并在确认协议里写一行"试点：免做，理由：…"。
