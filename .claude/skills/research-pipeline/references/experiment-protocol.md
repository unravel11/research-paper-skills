# R2 实验协议：把主线变成冻结的可执行协议

目的：在看到任何结果之前，把"怎么判"写死，使后面的结果无法被解释成任意方向。正式协议之前可以先做试点（[pilot-protocol.md](pilot-protocol.md)），试点只用来定阈值、种子数和分支，不用来凑结论。协议文件是日期命名的 markdown，放在 `experiments/`，冻结后只能追加"补充协议"，不能改原文。

## 协议文件结构

```markdown
# PROTOCOL_<YYYYMMDD>_<短名>

## 来源
- 对应 FRAMING 的主张与 RQ：
- 本协议覆盖的 RQ：
- 试点（experiments/PILOT_*.md）的结论，或“试点：免做，理由：”：
- venue 候选（paper/VENUE_PROFILE.md）要求覆盖的 essential 属性并集：

## 数据
- 来源、快照 / 版本、划分方式（train / dev / test）、泄漏检查方式
- 保护集规则（哪些集合不得读取、谁有权解锁）
- 查询与候选的表示（允许字段、脱敏规则）

## 比较
- 每个 RQ：处理组、对照组、最强基线及其版本来源、配对单位
- 主要指标与次要指标；统计方法（配对 bootstrap 次数与种子、检验）

## 结果中性检查
- 阳性对照 / 操作检查 / 数据质量检查各是什么，通过标准是什么
- 任一项不通过时，对应 RQ 的结论写“不能判定”，不写“不成立”

## 判定规则（每个 RQ 一条）
- 阈值与方向（非劣界 / 最小有意义差异 / AUROC 边界）
- 种子策略：种子数、种子一致性规则（全部同号且均值过线才算稳定）
- dev 用途（只用于完成性检查、温度拟合、决定进入 test 的配置）；test 每格只跑一次
- 不能判定时写什么

## 运行与冻结
- 训练 / 评估 / 分析脚本的路径与 SHA-256（表格形式 `| 路径 | SHA-256 |`，用 `research-pipeline/scripts/hash_files.py` 生成；`check_gates.py` 会逐行复核）
- 环境（硬件、框架版本、依赖锁定）
- 预计算力与时间；失败重跑规则

## 事后分析政策
- 任何看过结果后新增的分析，登记在"事后分析"节，标 post hoc 与触发原因，不得使用本协议的判定规则升格

## 授权
- 引用用户的具体授权（日期、原话）；训练 / API / 真实数据 / 保护集各自独立
```

## 冻结前检查单

- [ ] 每个 RQ 有且只有一个主要比较；基线是当前最强版本。
- [ ] 结果中性检查已写，阴性结果可解释。
- [ ] 试点已做并写回潜力卡与骨架分支，或已写明“试点：免做，理由”。
- [ ] 协议覆盖 venue 候选的 essential 属性并集；放弃的 desirable 属性和退出的候选已写明。
- [ ] 判定规则在看到任何 test 结果前写定；规则里没有"视情况"。
- [ ] 种子一致性规则已写；单种子只能产出"单种子观察"。
- [ ] dev / test 用途分开写清；保护集规则明确。
- [ ] 脚本哈希已记录；分析脚本也在内（以往漏记分析脚本导致威胁有效性要专门交代）。
- [ ] 台账模板已建：证据条目的字段与 orchestrator 合同一致。
- [ ] 授权逐项引用用户决定，不由阶段推导。
- [ ] 用户确认协议后记录冻结时间与哈希。
- [ ] 协议文件已登记到 `research/STATE.md` 的阶段产出索引；`PROGRESS.md` 有 R3 的任务行与执行者。

## 常见错误（来自一篇论文的复盘）

- 看了 dev 或 test 结果再定主比较，事后只能在 FRAMING 里如实记产生时点。
- 单种子 1 点阈值当作稳定增益，换种子后没有复现。
- 用旧版本的基线对照，写成对当前方法的优势。
- 协议与运行脚本不一致却未记录差异。
