# R2 协议：把主线变成冻结的、可执行的计划

目的：在接触任何确认性结果之前，把"研究什么、怎么比、怎样算成立、怎样算无效"写死，让后面的结果没法被解释成任意方向。协议不限定研究类型：受控实验、基准评测、测量研究、工具评估、案例与访谈、用户实验、形式化证明、复现研究都用同一个骨架，类型特有的要求写在 [methods/](methods/README.md) 的研究类型档案里，协议开头声明用了哪一份。正式协议之前可以先做小规模试做，见 [pilot-protocol.md](pilot-protocol.md)。

## 协议文件结构

```markdown
# PROTOCOL_<YYYYMMDD>_<短名>
- 研究类型：<继承 paper/FRAMING.md 的声明；两种时主在前、次在后；与 FRAMING 不同时下一行写“类型变更理由：”并修订 FRAMING>
- 产生时点：事前 / 事后（事后写明已经看过哪些结果）

## 来源
- FRAMING 版本与分支骨架版本；试点结论（或免做理由）；VENUE_PROFILE 要求覆盖的属性

## 对象与数据
- 研究的对象是什么，从哪来，怎么选，范围与排除规则，样本量或对象数的理由
- 观察单位与分析单位（在哪一层重复才算独立的重复）
- 已经看过的部分：哪些数据、结果或参与者反馈在写协议前已经接触过
- 不碰的部分：保留给确认的数据、对象或参与者，谁有权解锁

## 比较或分析
- 每个 RQ 一个主要比较或主要分析；对照是什么；基线或对照的版本与来源
- 主张类型：描述 / 关联 / 预测 / 因果 / 机制（因果要写识别假设）
- 探索性分析单独列出，标"探索"

## 判定规则（每个 RQ 一条）
- 怎样算成立；怎样算不成立；怎样算不能判定（结果中性检查不过、数据不够、过程失败）
- 稳健性要求：重复几次、怎样算一致、区间怎么给、敏感性怎么做（按研究类型档案）
- 规则里没有"视情况"

## 结果中性检查
- 阳性对照、操作检查、数据或材料质量检查（档案给出该类型的具体形式）
- 不通过时的结论是"不能判定"，不是"不成立"

## 执行与冻结
- 执行步骤、环境与版本、负责人
- 指纹表：脚本、配置、量表、编码本、提示词等按档案列出（`| 路径 | SHA-256 |`，用 `scripts/hash_files.py` 生成）
- 冻结时间；冻结后只能追加补充协议，不能改原文

## 偏离与事后分析政策
- 偏离登记表：日期、内容、理由、谁决定、对结论的影响；偏离不能以结果为理由
- 看过结果后新增的分析一律登记在 RESULT 的"事后分析"节，标 post hoc 与触发原因，不升格为协议内结论

## 授权
- 逐项引用用户的具体决定（日期、原话）；训练、API、真实数据、保护数据、外发各自独立
```

## 冻结前检查单

通用部分，任何研究类型都要过；档案里还有该类型的追加项。

- [ ] 研究类型与 FRAMING 一致（改了写理由并修订 FRAMING）；档案要求的追加字段已填。
- [ ] 每个 RQ 有且只有一个主要比较或主要分析；探索性分析单独列出并标明。
- [ ] 判定规则写了成立、不成立、不能判定三种结局，在接触任何确认性结果之前写定；没有"视情况"。
- [ ] 稳健性要求已写：重复运行写一致性规则，抽样写区间，定性写饱和与信度，理论写假设的最小集合。
- [ ] 结果中性检查已写，阴性结果可解释。
- [ ] 对象与数据的来源、选择、排除、已看过的部分、不碰的部分写清。
- [ ] 对照或基线是当前最强版本，版本来源写明。
- [ ] 试点已做并写回潜力卡与骨架分支，或已写明"试点：免做，理由"。
- [ ] 协议覆盖 venue 候选 essential 属性的并集；放弃的 desirable 属性和退出的候选已写明。
- [ ] 指纹表已记录，分析脚本也在内（以往漏记分析脚本导致威胁有效性要专门交代）。
- [ ] 偏离登记表已建；台账模板已建，字段与 orchestrator 合同一致。
- [ ] 授权逐项引用用户决定，不由阶段推导。
- [ ] 用户确认协议后记录冻结时间与指纹；协议登记到 `research/STATE.md` 的阶段产出索引；`PROGRESS.md` 有 R3 的任务行与执行者。

## 常见错误

- 看了结果再定主要比较，事后只能在 FRAMING 里如实记产生时点。
- 单次观察写成稳定结论；重复后没有复现。
- 用旧版本的对照，写成对当前方法的优势。
- 协议与实际执行不一致却没有登记偏离。
- 把试点当证据：试点看过的数据再拿来做确认。
- 探索性分析事后写成预先设定（HARKing）。
