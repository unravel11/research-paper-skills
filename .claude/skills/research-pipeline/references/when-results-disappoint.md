# 结果不如预期时的处置

结果和预期不一致时，先问它是哪一种，再决定做什么。四种原因的证据要求各不同；只有第一种允许"修了重跑"。

| 原因 | 判断它的证据 | 允许的动作 |
|---|---|---|
| 实现错误（bug、解析、泄漏、配置错） | 能指出具体缺陷并复现；修复后在同协议下的变化可解释 | 修 bug，同协议重跑；旧结果标 `SUPERSEDED_OR_INVALID` 并保留，在 RESULT.md 写 lineage |
| 数据问题（标签噪声、分布漂移、样本不足） | 独立于结果的结果中性检查不通过 | 结论写"不能判定"而不是"不成立"；是否补数据由用户授权，补了算补充协议 |
| 设计缺陷（比较不公平、指标不对应、功效不够） | 对照缺失或分析单元错误能在协议文本里指出 | 追加补充协议并标明是设计修正；原主要比较的结果仍然报告 |
| 真实阴性 | 结果中性检查通过，协议按规则执行，方向与预期相反或无差异 | 走骨架的不成立分支；这是发现，不是失败 |

## 不允许的动作

- 换主要比较、换指标、换子集、换基线版本，直到出现正结果。这些都是事后选择，只能作为 post hoc 标注的探索。
- 删掉不利的种子或格子；种子表完整列出。
- 把"不能判定"写成"不成立"，或把"不成立"写成"趋势一致"。
- 为了保住成立分支而放弃已有的阴性证据。

## 处置流程

1. 在 RESULT.md 的事后分析节登记异常：现象、怀疑的原因、要做的检查。
2. 跑结果中性检查，按上表归类。orchestrator 的异常分类同用：疑似缺陷 / 不可复现或未决 / 可复现的异常。
3. 归类为真实阴性时进入故事结算，选不成立分支，venue 用退路候选；收获仍要具体到读者会改变的决定。
4. 每一步写进 PROGRESS.md 并登记复核者；是否补实验由用户按潜力卡的重评决定。

阴性与边界结果是合法的贡献类型（见 paper-framing 第七节的路线），条件是读者读完能改变一个判断。

可复现、但不属于本文问题的异常，在 RESULT.md 的事后分析节登记后，可以作为新方向走 `innovation-explore` 的异常入口（先排伪像、再刻画、再查文献），不在本文里扩张。
