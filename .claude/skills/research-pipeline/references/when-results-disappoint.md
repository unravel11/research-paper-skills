# 结果不如预期时的处置

先归因，再决定能做什么。四类原因的证据要求和允许的动作不同；不同研究类型下"实现"和"数据"指的东西不同，例子按类型给。

| 原因 | 判断它的证据 | 允许的动作 |
|---|---|---|
| 实现错误：代码 bug、解析错、配置错、泄漏；编码本用错、量表计分错、证明步骤笔误 | 能指出具体缺陷并复现；修复后在同一协议下重做能说明差异来自缺陷 | 修复后同协议重做，登记为偏离并写明原因 |
| 数据或材料问题：标签噪声、分布漂移、样本不足；回应率低、受访者不匹配；对象集不代表目标 | 独立于结果的结果中性检查不通过 | 结论写"不能判定"；补数据或材料要写补充协议，不改判定规则 |
| 设计缺陷：对照缺失、比较不公平、分析单位错、功效不够、提纲引导、假设过强 | 对照缺失或单位错误能在协议里指出 | 回 R1 或 R2 重做设计；不在当前协议下打补丁 |
| 真实阴性 | 结果中性检查通过，协议按规则执行，方向与预期相反或无差异 | 走骨架的不成立分支；阴性是发现，照实写 |

## 不允许的动作

- 换指标、换分母、换参照、换时间窗、换阈值，直到结果好看。
- 只报成功的对象、运行或引语，不报失败的。
- 把探索性分析里找到的差异写成预先设定的结论。
- 以结果为理由偏离协议。

## 处置流程

1. 先做结果中性检查的复核，确定是哪一类。
2. 登记到 RESULT 的偏离或事后分析节，写明归因与证据。
3. 按上表的允许动作做；需要回退就在 `research/STATE.md` 写"回退到 R<n>，原因"。
4. 真实阴性进入结算：选不成立分支，走它的 venue 去处。
